# Data Retention Matrix

| Entity class / examples                                                                 | Classification                                                                    | Rule                                                                                       |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| JournalEntry/JournalLine/JournalSourceLink                                              | Immutable after posting                                                           | No UPDATE/DELETE; reversal/adjustment only                                                 |
| Posted Payment, allocations, reversals, Refund, TenantCredit movements                  | Append-only financial                                                             | Preserve source and correction chain                                                       |
| DepositTransaction/settlement/deduction/transfer                                        | Append-only/immutable after posting                                               | Preserve liability evidence and disputes                                                   |
| OwnerStatement issued lines, payable snapshot used for payout, paid payout/attempts     | Immutable financial snapshots                                                     | New supplemental/restated version; never overwrite                                         |
| Signed LeaseVersion, signed service/master contracts, signature evidence                | Immutable                                                                         | Amend/renew/terminate with linked records                                                  |
| AuditLog, ApprovalDecision                                                              | Append-only                                                                       | No physical deletion; redact only through approved privacy process that preserves evidence |
| OutboxEvent identity/payload, InboxConsumption                                          | Append-only after processing                                                      | Retry metadata may change; event fact/id remains                                           |
| UtilityAllocation posted inputs/lines, posted Expense/VendorBill recognition            | Immutable financial source                                                        | Reverse/adjust; never recalculate in place                                                 |
| Property, Building, RentableSpace, ServiceEngagement, Lease, MasterLease                | Archive/deactivate only after activation/reference                                | Historical relationships remain reachable                                                  |
| Party and typed profiles                                                                | Archive/deactivate; selective anonymization after retention                       | Company-level identity must not be duplicated/deleted when referenced                      |
| Ownership, entitlement, branch assignment, space versions/hierarchy, schedules/policies | Append-only effective-dated                                                       | End-date and add successor                                                                 |
| Account, Role, Permission, types/categories, amenities                                  | Normal mutable reference before use; deactivate after use                         | Codes used by history cannot be repurposed                                                 |
| Lead/Application/Reservation/Listing/Viewings                                           | Hard delete only abandoned unreferenced draft; otherwise archive/retention policy | Screening data may have shorter redaction retention                                        |
| MaintenanceRequest, WorkOrder, Inspection, Quotation                                    | Hard delete only invalid unactivated draft; otherwise archive                     | Preserve safety, vendor, and cost evidence                                                 |
| Document metadata/versions                                                              | Immutable version; archive/legal-hold aware                                       | Binary deletion only when retention allows and no legal/financial reference remains        |
| Notification/Delivery                                                                   | Retention-limited append history                                                  | Content/contact minimization and expiry                                                    |
| IdempotencyRecord                                                                       | Hard delete after safe expiry window                                              | Never remove while provider retry/replay remains possible                                  |
| Quarantined upload, failed import staging, rebuildable read models                      | Hard delete allowed                                                               | Not authoritative; cleanup is audited where sensitive                                      |

There is no universal `deletedAt`. Legal hold overrides normal retention. Privacy redaction must not destroy amounts, dates, references, or evidence required for financial/contractual integrity.
